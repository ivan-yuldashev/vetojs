# Серверный рендеринг

**[English](ssr.md) · [Русский](ssr.ru.md)**

Правила — это JSON, поэтому с сервера на клиент они едут тем каналом, которым фреймворк и так передаёт данные. Адаптер не нужен:

```tsx
const ability = buildAbility(ac, policyFor(currentUser));

<AbilityProvider rules={ability.rules}>
	<Toolbar post={post} />
</AbilityProvider>
```

| Фреймворк | Где проходят правила |
|---|---|
| Next, App Router | серверный компонент рендерит провайдер; модуль, где вызывается `createVetoContext`, — модуль `"use client"` |
| SvelteKit | `+layout.server.ts` возвращает их, дочерние маршруты читают `data` |
| React Router | их возвращает `loader`, а читает `useLoaderData()` |
| Nuxt | route middleware заполняет `useState("rules", …)` из серверного контекста |
| Astro | страница передаёт их острову пропсами |

```ts
// +layout.server.ts
export const load = ({ locals }: { locals: { user: { id: string } } }) => ({
	rules: policyFor(locals.user),
});
```

## Что уезжает на клиент

- **Правила.** Они уже относятся к одному пользователю.
- **Источники остаются на сервере** — сессия, членства, утверждения, из которых правила получились.
- **Считайте правила видимыми.** Любопытный пользователь их прочтёт, так что правило с id воркспейса, который ему иначе не виден, — утечка.

## Статическая страница вердикта не несёт

У статически собранной страницы нет пользователя: вердикт, запечённый в неё, — ни о ком, а после кеширования на CDN — обо всех. Отдайте публичную оболочку и закрывайте после гидрации или закрывайте на edge, где у запроса есть пользователь. Никогда не запекайте правила одного пользователя в страницу, которую получат другие.

## Сервер всё равно проверяет

Спрятанный элемент — это вежливость: запрос, который он прятал, можно отправить руками. Проверяйте перед действием — [гвардом](./guard.ru.md) или `ability.cannot(...)` в загрузчике или серверном компоненте.

## Почему так устроено

- **Правила — данные, а не объект**, поэтому переживают границу сериализации; экземпляр класса её бы не пережил.
- **Один массив с обеих сторон** — собран один раз, читается в двух местах, разъехаться нечему.
