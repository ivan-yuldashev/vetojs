# Условия по связям

**[English](relations.md) · [Русский](relations.ru.md)**

Многие живые правила говорят не о самой строке: *блог поста принадлежит моему воркспейсу*, *ни один комментарий не помечен как спам*. Связь для этого — просто ещё один ключ в `where`.

```ts
allow("update", "post", {
	where: {
		status: "published",                     // поле
		author: { role: "admin" },               // связь «к одному»
		comments: { none: { spam: true } },      // связь «ко многим»
	},
});
```

`createRules(ac)` знает ваши объявления, поэтому отличает поле от связи «к одному» и «ко многим»; TypeScript — тоже. Неверное имя связи, «к одному» вместо «ко многим», опечатка в поле связанного ресурса — всё это ошибки компиляции.

Связи вкладываются на любую объявленную глубину:

```ts
where: { blog: { workspace: { id: workspaceId } } }
```

## Кванторы

Для связи «ко многим» придётся указать, *сколько* связанных строк должны подойти:

| | Выполняется, когда |
|---|---|
| `some` | подходит хотя бы одна связанная строка |
| `every` | подходят все |
| `none` | не подходит ни одна |

На пустом наборе `some` даёт ложь, а `every` и `none` — истину: это обычное прочтение «все из ничего» и «ни одного из ничего».

Связи «к одному» квантор не нужен: условие вкладывается напрямую и выполняется, если ему удовлетворяет единственная связанная строка.

## Загружать связи — ваша задача, и забывчивость не остаётся тихой

Чтобы ответить на вопрос *админ ли автор поста*, автор должен лежать на объекте. Если его там нет, движок **бросает** `RelationNotLoadedError` вместо того, чтобы принимать решение.

Так сделано намеренно. Считай движок отсутствие данных за «не совпало» — забытый `include` тихо менял бы политику, а для `deny` это означало бы, что запрет незаметно перестал действовать.

Движок читает то же соглашение, которому уже следует ваш ORM:

| Что на объекте | Как понимается | Результат |
|---|---|---|
| `undefined` (ключа нет) | не загружено | **исключение** |
| `null` | загружено, там пусто | пустой набор |
| объект или массив объектов | загружено | обычное вычисление |
| строка / число / bigint | вы выбрали идентификаторы, а не строки | **исключение** — связь на самом деле не загружена |
| что-то ещё | испорченные данные | «неизвестно» → `allow` не даёт ничего, `deny` срабатывает |

Prisma, Drizzle и TypeORM следуют ему все: `include`/`with` отдаёт объекты или `null`, а связь, которую вы не запрашивали, остаётся `undefined`.

Читает движок обычные данные — объект, у которого прототип `Object.prototype` или которого нет вовсе. Prisma и Drizzle отдают ровно это. TypeORM отдаёт **экземпляры классов-сущностей**, и проверка по такому объекту ответит «нет»: движок не читает поля через незнакомый ему прототип. Разложите сущность на входе:

```ts
const entity = await repository.findOne({
	where: { id: postId },
	relations: { author: true },
});

ability.can("read", "post", { ...entity });
```

```ts
const post = await db.query.posts.findFirst({
	where: eq(posts.id, id),
	with: { author: true, comments: true },   // нужны правилам выше
});

ability.can("update", "post", post);
```

## `markLoaded` — когда соглашение не работает

Для объектов, собранных руками, или ORM, нарушающего соглашение, скажите это явно:

```ts
import { markLoaded } from "@vetojs/core";

const withAuthor = markLoaded(post, "author", author);
const withoutBlog = markLoaded(post, "blog", null); // загружено и пусто
```

Функция возвращает **копию**, ваш объект не меняется: в копии лежат значение и невидимая метка (глобальный символ, поэтому его не видят ни `Object.keys`, ни `JSON.stringify`).

Передать `undefined` в качестве значения нельзя — будет исключение: `undefined` как раз и означает «не загружено», так что пометить им связь загруженной — противоречие. Для «загружено и пусто» есть `null`.

## Почему так устроено

- **Отсутствие данных даёт исключение, а не «не совпало».** Забытый `include` — ошибка в запросе, а ошибки, тихо меняющие решения о доступе, — самые неприятные из всех.
- **Идентификатор вместо объекта тоже приводит к исключению.** Выбрать `authorId` вместо автора — самый частый вид «не загружено», и он заслуживает такого же громкого отказа, а не сравнения со строкой.
- **Прочий мусор даёт «неизвестно», а не ошибку.** Булево значение или случайный `null` внутри массива — не состояние загрузки, а испорченные данные: они играют на запрет в обе стороны, но запрос не роняют.
- **Вложенность достаётся бесплатно.** `where` у связи — обычное условие, поэтому связи внутри связей не требуют ничего особенного.
