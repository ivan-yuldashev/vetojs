# Связи

**[English](relations.md) · [Русский](relations.ru.md)**

Связь, объявленная в [`defineAbilities`](./define-abilities.ru.md), — это ещё один ключ в `where`:

```ts
allow("update", "post", {
	where: {
		author: { role: "admin" },                           // один к одному
		comments: { none: { spam: true } },                  // один ко многим
		blog: { workspace: { id: { in: workspaceIds } } },   // вложенно
	},
});
```

Неверное имя связи, поле, которого нет у связанного ресурса, или «один ко многим» без квантификатора не компилируются.

| Квантификатор | Выполняется, когда | На пустом списке |
|---|---|---|
| `some` | подходит хотя бы одна связанная строка | нет |
| `every` | подходят все | да |
| `none` | не подходит ни одна | да |

Связь «один к одному» принимает условие напрямую.

## Загружайте то, что читают правила

Если правило читает `post.author.role`, автор должен лежать на строке. Если его нет, `can()` **бросает** `RelationNotLoadedError`, а не решает — даже когда другая часть условия уже дала ответ:

```ts
const post = await db.query.posts.findFirst({
	where: eq(posts.id, id),
	with: { author: true, comments: true },
});

ability.can("update", "post", post);
```

| На строке | Как читается |
|---|---|
| ключа нет или `undefined` | не загружено — исключение |
| строка или число | id, а не строка — исключение |
| `null` | загружено, пусто: «один к одному» ничему не соответствует, «один ко многим» — пустой список |
| объект или массив объектов | загружено |
| что-то другое | мусор — «неизвестно»: `allow` ничего не разрешает, `deny` срабатывает |

Prisma и Drizzle отдают строки именно в таком виде. Движок читает только простые объекты, поэтому экземпляры классов — сущности TypeORM — превратите в объекты через `structuredClone(entity)`: он заодно превращает и связанные сущности. Спред копирует только верхний уровень.

Строке, собранной руками, нужен ключ связи: `{ ...post, author }`. `markLoaded(post, "author", author)` делает то же самое и не принимает `undefined`; для «загружено, но пусто» передайте `null`.

В SQL связь становится подзапросом `EXISTS` — см. [Drizzle-адаптер](./drizzle.ru.md#связи).

## Почему так устроено

- **Незагруженная связь — исключение.** Если читать её как «не совпало», забытый `include` тихо поменяет политику, а `deny` перестанет действовать.
- **id вместо строки — тоже исключение.** Выбрать `authorId` вместо автора — самый частый способ забыть загрузку.
- **Прочий мусор — «неизвестно», а не ошибка**, поэтому испорченные данные отказывают, а не роняют запрос.
