# Как принимается решение

**[English](rule-evaluation.md) · [Русский](rule-evaluation.ru.md)**

> **Подошедший `deny` всегда побеждает. Всё, что не разрешено, запрещено.**

## Какие правила участвуют

Правило участвует, если совпал ресурс и совпало действие — названо прямо, есть в списке или это `"manage"`. Дальше:

- его `where` сверяется со строкой; правило без `where` действует на все строки;
- его `when` сверяется с [окружением](./define-abilities.ru.md#окружение-запроса) запроса. `allow` участвует, только когда его `when` выполнено; `deny` выбывает, только когда его `when` не выполнено. Ключ, которого в окружении нет, ничего не опровергает, поэтому пропавшее значение запрет не снимает. Если окружение не подставлено, `allow` с `when` ничего не разрешает, а `deny` с `when` действует.

## Решение

1. Есть подошедший `deny` → запрещено.
2. Иначе есть подошедший `allow` → разрешено.
3. Иначе → запрещено.

```ts
const rules = [
	allow("update", "post"),
	deny("update", "post", { where: { status: "published" } }),
];

ability.can("update", "post", { ...post, status: "draft" });     // true
ability.can("update", "post", { ...post, status: "published" }); // false
```

Порядок правил в массиве ни на что не влияет.

## Когда данные не подходят

Условие может ответить **«неизвестно»** — поле не того типа, испорченная связь ([операторы](./operators.ru.md)):

| Условие отвечает | `allow` | `deny` |
|---|---|---|
| да | разрешает | запрещает |
| неизвестно | ничего не разрешает | **запрещает** |
| нет | ничего не разрешает | не действует |

`deny` отступает, только когда его условие для этой строки однозначно ложно, поэтому значение не того типа мимо запрета не проскочит.

Проверка без строки задаёт другой вопрос — см. [со строкой или без](./ability.ru.md#со-строкой-или-без).

## Почему так устроено

- **Приоритет зафиксирован, а не настраивается.** Поэтому те же правила компилируются в SQL как `allows AND NOT denies` без всякого решателя, и запрос возвращает ровно то, что разрешает `can()`.
- **Про `manage` не спрашивают.** В правиле он подходит к любому действию; проверка, которая его называет, не выбирает ни одного правила и получает отказ.
