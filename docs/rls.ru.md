# Рядом с Postgres row-level security

**[English](rls.md) · [Русский](rls.ru.md)**

RLS в Postgres решает, какие строки видит соединение. veto решает то же самое, а ещё — какие поля можно писать, что показывает интерфейс и до чего может дотянуться вызов инструмента агентом. Использовать оба разумно; считать, что одно покрывает другое, — нет.

| | RLS | veto |
|---|---|---|
| Какие строки вернёт запрос | ✅ обеспечивает база | ✅ компилируется в `WHERE` |
| Какие поля и значения можно писать | ✖ `GRANT UPDATE (col)` привязан к роли, а не к пользователю или строке | ✅ `fields` и `values` |
| Доступ в интерфейсе | ✖ в браузер ничего не попадает | ✅ правила уезжают JSON |
| Ресурс без таблицы | ✖ не к чему привязать политику | ✅ обычное правило |
| Базы помимо Postgres | ✖ | ✅ |

Работающее сочетание: **RLS — пол, veto — контракт.** База не отдаст строки, даже если запрос забыл фильтр; приложение решает про запись поле за полем.

## Три способа, которыми RLS не защищает ничего

**Владелец таблицы обходит RLS.** Соединения приложения часто и есть владелец, и тогда любой запрос возвращает все строки:

```sql
alter table posts enable row level security;
alter table posts force  row level security;
```

**Настройка сессии вне транзакции утекает.** Простой `SET` живёт столько же, сколько соединение, а за пулером это соединение достанется и следующему запросу. Задавайте пользователя через `SET LOCAL` внутри транзакции:

```sql
begin;
set local "veto.actor" = 'u1';
-- запросы здесь
commit;
```

**Политики объединяются через OR.** Каждая политика `PERMISSIVE` расширяет доступ; запрет нужно писать `AS RESTRICTIVE`, и одно забытое слово превращает его в пустышку.

## Выражение политики

Условие, которое компилирует veto, уже имеет нужную для `USING` форму — никогда не `NULL`, связи как `EXISTS`, — но в нём значения одного пользователя. У политики пользователя нет, поэтому значение берётся из сессии:

```
using ("posts"."author_id" is not distinct from current_setting('veto.actor', true))
```

## Почему так устроено

- **База — единственное место, где забытый фильтр не протечёт**, и это стоит иметь даже в аккуратном приложении.
- **Два источника правды расходятся.** Политика — это DDL, который накатывает миграция, правила — код, который деплоится постоянно, и ничто их не сверяет. Держите RLS на уровне пола.
- **Предикаты и здесь должны быть двузначными.** `NOT` над `NULL` в `USING` молча переворачивает видимость строки — ровно та ошибка, которую [Drizzle-адаптер](./drizzle.ru.md) отказывается генерировать.
