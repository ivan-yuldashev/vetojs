# Короткая запись полей

**[English](condition-shorthand.md) · [Русский](condition-shorthand.ru.md)**

Условия пишутся объектами, а не деревьями. Запись `{ status: "published" }` говорит сама за себя, а храниться будет древовидная форма `{ field: "status", op: "eq", value: "published" }`. Здесь — про тот небольшой язык, что лежит между ними.

```ts
{ status: "published" }        // просто значение означает «равно»
{ views: { gt: 100 } }         // объект с оператором
{ status: "draft", views: 0 }  // соседние ключи объединяются через И
```

## Какие операторы доступны полю

Набор операторов зависит от типа поля, поэтому неподходящий оператор оборачивается ошибкой компиляции, а не правилом, которое никогда не сработает:

| Тип поля | Доступно |
|---|---|
| любой | `eq` `ne` `in` `nin` `exists` |
| `number`, `Date` | плюс `gt` `gte` `lt` `lte` |
| `string` | плюс `contains` |

```ts
allow("read", "post", { where: { title: { gt: 5 } } });       // ✗ у строк нет порядка
allow("read", "post", { where: { views: { contains: 1 } } }); // ✗ contains только для строк
```

Для поля-объединения вроде `status: "draft" | "published"` годится любой вариант из этого объединения.

## Значение или объект с оператором

Значение считается объектом с оператором только тогда, когда это обычный объект ровно с одним ключом и ключ этот — один из тринадцати операторов. Всё прочее сравнивается как значение:

```ts
{ tags: ["a", "b"] }         // сравнение с этим массивом — всегда «неизвестно»
{ tags: { in: ["a", "b"] } } // вхождение — скорее всего, вы имели в виду это
{ createdAt: someDate }      // равно этой дате
```

Массивы и `Date` — это всегда значения, никогда операторы.

`Date` сравнивается по метке времени. А массив или объект не сравнивается ни с чем: два структурно одинаковых объекта — это разные ссылки, поэтому ответ «не равно» был бы догадкой, и движок отвечает **«неизвестно»** — оно не даёт ничего и заставляет сработать любой `deny`. Ровно поэтому типы отклоняют голый массив у поля-массива; берите `in` или [связь](./relations.ru.md).

## Даты становятся числами

`Date` в любом месте условия — сама по себе, внутри объекта с оператором или элементом списка `in` — сохраняется числом миллисекунд. Благодаря этому правило остаётся чистым JSON и без потерь переживает `JSON.stringify` и поездку через базу.

При проверке помнить об этом не нужно: поле `Date` из вашего ORM корректно сравнится с сохранённым числом, и наоборот.

## Где применяется

- **`where`** — полная версия: поля плюс ключи связей и `and` / `or` / `not`. См. [условия](./conditions.ru.md) и [связи](./relations.ru.md).
- **`values`** — урезанная: только поля и `and`. Разрешение значений — плоский список допустимого, а `or` и `not` над ним выражали бы запреты, которым место в правиле `deny`. См. [запись](./mutations.ru.md).

## Почему так устроено

- **Короткая запись разворачивается при создании правила**, а не при вычислении. Ничего «сокращённого» не попадает ни в хранилище, ни в сеть, ни в компилятор SQL: все они видят одно и то же обычное дерево.
- **Голое значение означает `eq`**: это подавляющее большинство случаев, а `{ status: { eq: "published" } }` добавляет шум, но не смысл.
