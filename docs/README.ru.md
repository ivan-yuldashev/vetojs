# Документация

**[English](README.md) · [Русский](README.ru.md)**

По странице на каждое понятие, и в каждой описано, как код ведёт себя на самом деле. Если с библиотекой вы ещё не знакомы, начните с [обзора проекта](../README.ru.md).

> По соглашению проекта комментариев в исходниках нет — все объяснения собраны здесь. Каждая страница о понятии заканчивается разделом «Почему так устроено».

## Если код пишет ассистент

- **[Для агентов](./for-agents.ru.md)** — весь API на одной странице, верные идиомы и ошибки, которые выглядят правдоподобно.

## Если вы приходите с CASL

- **[Переход с CASL](./migrate-from-casl.ru.md)** — соответствие API, операторы без аналогов, react- и RSC-часть, и два отличия в поведении, которые меняют смысл вашей политики.

## Как запустить политику

1. **[Объявление ресурсов](./define-abilities.ru.md)** — `defineAbilities`: что существует и что с этим можно делать. Всё остальное выводится отсюда.
2. **[Что такое правило](./rules.ru.md)** — модель данных и уровни ряда, поля и значения.
3. **[Как писать политику](./create-rules.ru.md)** — `createRules`: типизированные `allow` и `deny`.
4. **[Как проверять доступ](./ability.ru.md)** — `buildAbility`: `can`, `authorize`, `permittedFields`, `validate`.

## Применение правил

- **[Как принимается решение](./rule-evaluation.ru.md)** — приоритет запрета, запрет по умолчанию и поведение на плохих данных.
- **[Запись](./mutations.ru.md)** — какие поля и какие значения можно писать.
- **[Фильтрация в базе](./where.ru.md)** — те же правила в виде SQL `WHERE`, с гарантией совпадения с `can()`.
- **[Правила извне](./parse.ru.md)** — `parseRules`: проверка недоверенного JSON на границе.

## Использование в приложении

- **[`@vetojs/react`](./react.ru.md)** — `<Can>`, `useAbility`, `AbilityProvider`: те же правила в интерфейсе.
- **[`@vetojs/core/guard`](./guard.ru.md)** — `createGuard`: пользователь, строка и данные проверены до того, как отработает server action.
- **[`@vetojs/drizzle`](./drizzle.ru.md)** — `defineTables` и `filter`: политика как SQL `WHERE`, сверенная построчно с настоящим Postgres.
- **[Express, Fastify, Hono](./http.ru.md)** — гвард в обычном HTTP-обработчике и те несколько строк, которые добавляет каждый фреймворк.
- **[Серверный рендеринг](./ssr.ru.md)** — как правила уезжают клиенту помимо RSC и почему статическая страница не может нести вердикт.
- **[Агенты](./agents.ru.md)** — вызовы инструментов под той же политикой и отказ, на который модель может отреагировать.
- **[Row-level security в Postgres](./rls.ru.md)** — как жить с обоими и три способа защититься только на бумаге.
