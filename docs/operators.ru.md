# Операторы

**[English](operators.md) · [Русский](operators.ru.md)**

Что отвечает каждое сравнение — в том числе на данных, которые ему не подходят. Как их писать, описано в разделе [условия](./conditions.ru.md).

| Оператор | «Да», когда | Примечания |
|---|---|---|
| `eq` | значения равны | `Date` сравнивается по времени, в том числе с числом миллисекунд; `1` равно `1n`; строки сравниваются с учётом регистра |
| `ne` | не `eq` | поле `null` не равно никакому другому значению |
| `in` / `nin` | значение есть / нет в списке | принадлежность проверяется через `eq`; в списке может быть `null` |
| `gt` `gte` `lt` `lte` | сравнение по порядку | обе стороны числовые (number, bigint, `Date`) или обе строки |
| `contains` | строка содержит подстроку | с учётом регистра |
| `exists` | заполнено для `true`, пусто для `false` | `0`, `false` и `""` считаются значениями, `null` — пустотой |
| `has` | массив содержит элемент | |
| `hasAny` | массив содержит хотя бы один из списка | |
| `hasAll` | массив содержит все из списка | пустой список выполняется для любого массива |

## Когда данные не подходят

| Данные | Ответ |
|---|---|
| поля нет или оно `undefined` — под любым оператором, включая `exists` | **неизвестно** |
| поле `null` — под любым оператором, кроме `ne`, `nin`, `exists` | **нет** |
| значение другого типа: `"5"` против `5`, `"true"` против `true` | **неизвестно** |
| `NaN`, невалидный `Date` | **неизвестно** |
| объект или массив, сравниваемый по значению | **неизвестно** |
| элемент массива или член списка другого типа, если ни один другой не совпал | **неизвестно** |
| `has` / `hasAny` / `hasAll` на значении, которое не массив | **неизвестно** |
| `in` / `nin`, у которого список не список | **неизвестно** |
| оператор, которого движок не знает | **неизвестно** |

`allow` на «неизвестно» ничего не разрешает, а `deny` срабатывает, поэтому кривые данные могут только сузить доступ — см. [как принимается решение](./rule-evaluation.ru.md#когда-данные-не-подходят). Правила с испорченным списком, незнакомым оператором, `NaN` или ±`Infinity` ещё раньше отвергает [`parseRules`](./parse.ru.md).

```ts
// deny("read", "post", { where: { secret: true } })
const row = JSON.parse('{ "id": "p1", "secret": "true" }');
ability.can("read", "post", row); // false — неизвестно, запрет срабатывает

// deny("read", "post", { where: { status: "archived" } })
ability.can("read", "post", { id: "p1" }); // false — status нет, запрет срабатывает
```

## `null` — это значение

`eq null` выполняется только для поля `null`, `ne null` — для любого другого значения. С любым значением, кроме себя самого, поле `null` даёт обычное «нет» — так же SQL отвечает про колонку `NULL`. Отсутствующее поле — не `null`: о значении оно ничего не говорит, поэтому ответ — «неизвестно».

| Правило | `null` | `"draft"` | поля нет |
|---|---|---|---|
| `{ status: "draft" }` | нет | да | неизвестно |
| `{ status: null }` | да | нет | неизвестно |
| `{ status: { ne: "draft" } }` | да | нет | неизвестно |
| `{ status: { ne: null } }` | нет | да | неизвестно |
| `{ status: { exists: false } }` | да | нет | неизвестно |

## Почему так устроено

- **Никакого приведения типов.** Postgres сравнит `'200'` с `200` как числа, JavaScript сравнит `"10" < "9"` как строки. Здесь значение не того типа — «неизвестно», а не тихое совпадение.
- **Отсутствующее поле — «неизвестно», а не «нет».** Строка, выбранная без колонки, или ответ сериализатора, выбросившего ключи, ничего не говорит о значении. Прочитай его движок как «нет» — `deny` по этому полю отошёл бы в сторону, а `allow` с `ne` выдал бы доступ. Загружайте поля, которые читают правила.
- **`null` — значение.** База его хранит, и `can()` отвечает про него так же, как SQL про колонку `NULL`, поэтому запрос и проверка совпадают.
- **`nin` на испорченном списке — «неизвестно», а не «да».** Простое «нет» для `in` превратило бы его отрицание в разрешение.
- **Объект — «неизвестно», а не «не равно».** Два одинаковых на вид объекта — разные ссылки; ответ «не равно» обезоружил бы каждый `deny` по этому полю.
- **`1` равно `1n`**, потому что числовые идентификаторы постоянно переходят между `number` и `bigint`.

`ConditionOperator` экспортируется для кода, который обходит `ability.where()`, — например, для собственного адаптера базы.
