# Операторы

**[English](operators.md) · [Русский](operators.ru.md)**

Что отвечает каждое сравнение — в том числе на данных, которые ему не подходят. Как их писать, описано в разделе [условия](./conditions.ru.md).

| Оператор | «Да», когда | Примечания |
|---|---|---|
| `eq` | значения равны | `Date` сравнивается по времени, в том числе с числом миллисекунд; `1` равно `1n`; строки сравниваются с учётом регистра |
| `ne` | не `eq` | пропавшее поле или `null` — не равно |
| `in` / `nin` | значение есть / нет в списке | принадлежность проверяется через `eq` |
| `gt` `gte` `lt` `lte` | сравнение по порядку | обе стороны числовые (number, bigint, `Date`) или обе строки |
| `contains` | строка содержит подстроку | с учётом регистра |
| `exists` | есть для `true`, нет для `false` | `0`, `false` и `""` считаются значениями |
| `has` | массив содержит элемент | |
| `hasAny` | массив содержит хотя бы один из списка | |
| `hasAll` | массив содержит все из списка | пустой список выполняется для любого массива, но не для пропавшего поля |

## Когда данные не подходят

| Данные | Ответ |
|---|---|
| поле `null` или его нет — под любым оператором, кроме `ne`, `nin`, `exists` | **нет** |
| число против строки, `NaN`, невалидный `Date` | **неизвестно** |
| объект или массив, сравниваемый по значению | **неизвестно** |
| `has` / `hasAny` / `hasAll` на значении, которое не массив | **неизвестно** |
| `in` / `nin`, у которого список не список | **неизвестно** |
| оператор, которого движок не знает | **неизвестно** |

`allow` на «неизвестно» ничего не разрешает, а `deny` срабатывает, поэтому кривые данные могут только сузить доступ — см. [как принимается решение](./rule-evaluation.ru.md#когда-данные-не-подходят). Правила с испорченным списком или незнакомым оператором ещё раньше отвергает [`parseRules`](./parse.ru.md).

```ts
// deny("read", "post", { where: { secret: true } })
const row = JSON.parse('{ "id": "p1", "secret": "true" }');
ability.can("read", "post", row); // false — неизвестно, запрет срабатывает
```

## Почему так устроено

- **Никакого приведения типов.** Postgres сравнит `'200'` с `200` как числа, JavaScript сравнит `"10" < "9"` как строки. Здесь значение не того типа — «неизвестно», а не тихое совпадение.
- **`nin` на испорченном списке — «неизвестно», а не «да».** Простое «нет» для `in` превратило бы его отрицание в разрешение.
- **Объект — «неизвестно», а не «не равно».** Два одинаковых на вид объекта — разные ссылки; ответ «не равно» обезоружил бы каждый `deny` по этому полю.
- **`1` равно `1n`**, потому что числовые идентификаторы постоянно переходят между `number` и `bigint`.

`ConditionOperator` экспортируется для кода, который обходит `ability.where()`, — например, для собственного адаптера базы.
