# Фильтрация в базе — `where()`

**[English](where.md) · [Русский](where.ru.md)**

`ability.where(action, resource)` возвращает условие для запроса списка, и база отдаёт только то, что пользователю можно видеть:

```ts
const filter = ability.where("read", "post"); // простое дерево условий
```

С [Drizzle-адаптером](./drizzle.ru.md) это один вызов, а ваши собственные предикаты сужают результат:

```ts
const rows = await db.select().from(posts)
	.where(schema.filter(ability, "read", "post", eq(posts.status, "published")));
```

## Гарантия

```
can(action, resource, row)   ⟺   row matches where(action, resource)
```

Тест на соответствие прогоняет оба пути по сетке строк — `null`, пропавшие поля, чужие типы — и требует одинаковых множеств. Drizzle-адаптер гоняет на Postgres свою сетку, и `can()` читает строки в том виде, в каком их вернул драйвер.

## Как правила становятся одним условием

```
(любое условие allow)  AND NOT  (любое условие deny)
```

| Правила | Условие |
|---|---|
| ни один allow не подошёл | `{ or: [] }` — ни одной строки |
| безусловный allow | `NOT (denies)` |
| безусловный deny | `{ or: [] }` |
| allow и условные deny | `allows AND NOT denies` |

Строка попадает в выборку только при однозначном «да». «Неизвестно» её исключает — так же, как `WHERE` в SQL отбрасывает `UNKNOWN`.

## Для инструмента поиска у агента

Инструмент, который ищет или выводит список, должен отдавать то, что видно человеку, за которого действует агент. Фильтруйте до того, как что-то попадёт к модели:

```ts
import { ilike } from "drizzle-orm";

const searchPosts = async (term: string) =>
	db.select().from(posts)
		.where(schema.filter(ability, "read", "post", ilike(posts.title, `%${term}%`)));
```

Строки, которые уже лежат в памяти, — ответ стороннего API, вложенный список — по-прежнему проходят через `can()`.

## Свой адаптер

Обходите дерево; `ConditionOperator` называет операторы, а узел с `ref` сравнивает две колонки. Несовпадение типов компилируйте в `UNKNOWN` и никогда не приводите типы: Postgres, сравнив `'5000' > 1000` как числа, впустит строку, которую `can()` запрещает.

## Почему так устроено

- **Приоритет зафиксирован**, поэтому условие строится механически, без всякого решателя.
- **«Все строки» и «ни одной» — это пустые группы `{ and: [] }` и `{ or: [] }`**, так что потребителю не нужен отдельный тип узла.
